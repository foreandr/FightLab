UNIVERSAL COMBAT RUNTIME

The supported gameplay path is:
  mode input -> actor / authored spell -> CombatRuntime -> shared contacts,
  defenses, damage, statuses, resources and physical reactions.
Story and Create both use this path. Modes own selection, camera input, menus,
round objectives and UI. Combat-state presentation belongs to shared actors and
world services, not mode loops: burn, stun, chill, haste and frozen legs must not
branch on story_mode or editor_animation_only. Modes must not calculate hit damage,
subtract a second cast cost or implement a second projectile simulation.

STARTING A NEW MODE

Inherit res://scripts/combat_world.gd, not BattleArena, DuelArena or SpellArena.
CombatWorld is a Node3D with no menu, campaign or demo scene. It supplies actor
registration, services, simulation, hitbox toggles, prediction and event hooks.
Levels are separate geometry/data providers, bound through use_level; see
docs/combat-levels.txt. The default world is unbounded and imports no pit size.

Example GDScript (add your map, camera and light separately):

  extends "res://scripts/combat_world.gd"
  const Rules=preload("res://scripts/combat_spell_rules.gd")

  func _ready() -> void:
      super._ready()
      var player=spawn_combatant(0,Vector3.ZERO)
      var opponent=spawn_combatant(1,Vector3(0,0,4))
      player.brain_enabled=false
      opponent.brain_enabled=false
      round_active=true

  func fire(actor:CharacterBody3D,authored_spell:Dictionary) -> bool:
      var origin=fighter_hand(actor,str(authored_spell.get("hand","hand_r")))
      return combat().release(actor,authored_spell,origin)

The base physics callback advances actors, their real hurtboxes/melee contacts,
projectiles, channels and pulses. If you override it, call tick_combat(delta)
exactly once. Do not also call individual simulation steps in the same frame.
Existing arenas retain their visual and round-management loops and delegate
their simulation stages to the same runtime.

spawn_combatant uses the existing BattleActor and licensed character assets.
The actor owns animation players, locomotion, recovery, defenses, death and
status state. Give actors separate teams to make them enemies. Assign their
input through the shared character movement/focus/camera modules documented in
shared-character-mechanics.txt. story_mode is an existing campaign/control
adapter flag, not a requirement for firing spells through this API.

CASTING API

combat().release(actor,spec,origin,animation_profile={}) -> bool
  Checks active world, living actor, casting-limb availability, optional burst
  requirement, God Mode and both resource budgets. Commits mana and stamina
  atomically, then dispatches the effect. A failed request spawns nothing and
  spends neither resource. The profile supplies limb requirements, not costs.

combat().cast(actor,spec,animation_profile={}) -> bool
  Same request, using the spec's hand as origin. Handles projectile/ground,
  healing, haste, burst, beam, ice beam, nova and earth summon effects.
  Legacy armor dispatch is a compatibility no-op; armor is cosmetic.

Interrupted cast stamina
  begin_cast_attempt(actor,spec,time_to_release,mode_owned=true) snapshots the
  stamina cost and scheduled release time. Advance it with the animation's elapsed
  time using advance_cast_attempt(actor,elapsed). Interrupting/restarting an
  unreleased attempt spends cost * clamp(elapsed/time_to_release,0,1), limited to the
  actor's remaining stamina. Mana is not spent for that interruption.
  Thus 70% of the way to release costs 70%, irrespective of recovery time after
  release. Create converts the timing fraction to seconds; native casts supply
  the release point in the same clock units used by their animation sampler.
  Successful release pays the ordinary full cost once and clears the attempt;
  canceling its recovery cannot charge it again. God Mode remains unlimited.
  Native actor casts and Create use this same accounting. Native casts cancel
  automatically when they leave cast mode; externally driven previews pass
  mode_owned=false and explicitly interrupt on stop/switch/restart.
  Resetting a fighter discards its attempt along with the explicit full reset.

spawn_projectile and combat().dispatch are lower-level execution APIs for callers
that already committed a cast. Do not call them after release for the same cast.

projectile_launch_state / predict_projectile_impact are read-only forecasts.
Movement contribution is captured once at launch. Future caster velocity does
not change an in-flight projectile. AoE applies once per victim, not per limb.
Shared physical_momentum.gd uses horizontal speed equally for forward, backward,
sideways and diagonal motion. Vertical velocity contributes nothing. Projectile
speed increases along the existing aim direction, without sideways aim drift.

spell_impact_burst selects contact presentation from the spell rather than the
attacker's team. Melee and explicit elementless projectiles use a tight neutral
flash/contact marks via ElementalVFX.physical_contact; no flame, smoke or blast
ring. Elemental spells keep their existing bursts. Ground impacts use this same
selection. This changes presentation only, not impact physics, damage or costs.

combat_hit_regions.gd owns physical headshot scaling. apply_impact identifies the
actual receiving area, applies head 2x / other 1x once to its physical component
after shield absorption and before actor health handling, then separately
applies the original status spec. Burn/status potency and duration, mana/stamina,
knockback and nearby-ice damage do not inherit the headshot multiplier. Each AoE
victim resolves its own receiving area. Successful hits notify optional hitbox
highlights, and the common actor uses distinct existing head/chest reaction clips.

combat_defense_rules.gd defines the provisional 40-physical-damage threshold for
nonlethal hit ragdolls. Death retains its ragdoll path. Incoming impulse affects
motion, not the hit threshold. Cosmetic armor cannot absorb damage or impulse.
The authoring panel uses the same pure rule for unblocked body/head predictions.
Barrier/block changes, guard-break policy and a blocking dummy are deferred.

After a successful lethal physical head impact, Runtime calls the actor's optional
sever_head hook. BattleActor splits only that corpse's head skin and releases its
existing ragdoll head. Reset restores intact source meshes. Status tick deaths
never invoke this headshot-only hook, and God Mode/wooden dummies are excluded.

AUTHORING A SPELL

combat_spell_rules.gd owns physical cost/damage from animation duration, release
timing, normalized neutral damage, mana cost, amp, power allocation and authored
projectile specs. animation_mana_scaling.gd owns the existing mana/amp curve.

Rules.allocate(base,mix,element,total_power) applies the chosen power shares.
Rules.projectile_base builds elementless/elemental content without the UI;
Rules.neutral_projectile() is a ready-to-use authored default.
Rules.author(base,duration,release_fraction,offensive) returns a new spec with
final costs, damage, radius, velocity and potency. Rules.authored_stats returns
the matching UI values, including optional moving-caster preview. Author once;
execute that spec unchanged. Do not run author() again when equipping/casting it.

Explicit damage/mana/motion values take precedence. Legacy spell defaults are
content dictionaries, not alternate combat engines. Older duel content keeps
its original preset values while using the same execution pipeline. The neutral
crafted offensive spell remains 1 s, 50/50 size/speed, centered timing and full
power: 10 stamina and 10 damage against an unblocked stationary target.
Mana discounts use only time before release: duration * release_fraction.
The default 1s animation releases at 0.3s, costing ~16.25 mana from a 10 base.
A 4s Fire animation releasing at 30% waits 1.2s: ~17.41 mana before effect transfer.
Effect power now transfers the same fraction of animation stamina into pre-discount
mana. With 28.5% burn, that example transfers 11.4 of its 40 stamina: 28.6 stamina
and (20 + 11.4) * 0.87055 = ~27.34 mana. Damage/amp formulas are unchanged.
Follow-through earns no savings; one second before release is neutral and ten
seconds before release is free. Physical cost/damage and amp keep their own
existing duration rules. Authoring, payment and live calculation windows agree.
Limiter-off overrides stay in spell_test_overrides.gd; the UI's save rejection
still applies. Execution does not recouple independent testing values.

ANIMATION API

After an animated cast successfully releases, CombatRuntime.cast_committed(actor)
blocks voluntary restart/actions until finish_cast(actor). Create preserves the
released animation's duration/profile while draft sliders remain editable for
the next cast. Native actor tick_cast clears commitment on completion. Forced
hit/death mode exits can interrupt; explicit practice reset/scene teardown clears
the lock. Failed releases do not commit, and pre-release cancellation still pays
the completed fraction of stamina. Follow-through is not a second resource fee.

spell_cast_motion.gd samples native or imported animation profiles by normalized
progress. It preserves ice restrictions and supports explicit shared aim-pose
corrections. capture(actor) and blend_from(actor,pose,weight) are shared by cast
transitions and diagonal locomotion. Animation resources stay read-only and
AnimationPlayers remain per actor. animation_channels.gd owns cached filtering.

Mode-specific clocks, charge holds, editor scrubbing/undo and saved timelines
remain their respective controllers' responsibilities; these are authoring and
input state rather than alternate animation assets or damage implementations.
melee_contact.gd consumes an animation's swept limb/window and uses the shared
contact, charge, motion and impact rules. Callers only provide their animation
clock/state and mark a returned successful contact connected.

WORLD HOOKS

Experimental floating numbers

  Burn rules live in burn_rules.gd: 5 seconds, 0.5s tick interval, ~0.3912 base damage
  per tick (~0.7824 DPS / 3.9122 total at potency 1). This calibrates burn to the
  same marginal damage per power point as projectile speed on a 1s body hit.
  Potency/amplification scales damage, not the default duration.
  Actor ticking consumes only remaining active time and catches
  up missed ticks, including the final tick, so frame size cannot change totals.
  Character projectile impacts apply body burn without spawning ground fire.
  Surface impacts leave a five-second fire patch on the actual struck face.
  Wall fire/scorch stays at impact height and attaches to that wall; it is not
  projected onto the ground below. Floor fire stays on the floor. Flame tongues
  rise upward from surface-distributed anchors. Touching wall fire ignites the
  character in 3D; a high patch does not burn someone standing beneath it.
  Each patch ignites a character
  once for the same full burn; standing in it does not refresh the timer each
  frame. Existing explicit burn_duration data can extend either duration later.
  Authoring stats, RHS readouts and execution use these shared rules.
  Cleansing uses actor.cleanse_burn()/Burn.cleanse: clear the remaining duration,
  partial tick clock and source. Already dealt ticks remain; no future burn damage
  is prepaid or queued. Water and reset use the same call. Reapplication starts
  a fresh half-second interval, with no fractional time carried from a cleansed
  burn. The shared visual observes cleared burn state and fades out.
  tests/burn_behavior_test.gd covers actual collision, full totals, large/uneven
  steps, patch lifetime, walk-through ignition, continued burn after exit and amp.
  CombatWorld.set_combat_numbers(enabled) enables a per-world presentation layer.
  It defaults off; Spell creation exposes Numbers [3] and the unmodified 3/numpad
  3 shortcut. Resource spending emits actual successful stamina/magicka costs,
  including interrupted casts. Runtime impacts emit physical damage_taken deltas,
  so immortal training targets still show the actual hit while retaining health.
  Burn ticks emit their actual damage as red typed burn numbers every half-second,
  including immortal practice counters. Regeneration, failed transactions and
  unpaid God Mode costs do not emit numbers. Stamina is green, magicka blue;
  physical and burn damage are red and separately labeled.
  Labels follow their actor, rise, fade over 1.4 seconds and are capped at 32.
  Disabling clears them immediately; battle/practice reset clears old labels.
  combat_floating_numbers.gd owns this rendering; it never calculates or modifies
  damage, costs, physics or actor state. clear_combat_numbers() is the reset hook.

Override projectile_aim_target, combat_target and heal_target to choose targets.
Reuse combat_aim.gd for free aim and focused chest anchors.
Override projectile_visual, orient_projectile, combat_sound, impact_burst,
combat_cast_feedback, combat_heal_feedback and combat_impact_feedback for visuals,

REGRESSION CONTRACT

tests/combat_runtime_contract_test.gd deliberately uses a bare CombatWorld,
without either the Story or Create scene. It exercises real actor spawning,
atomic failure/success, actual neutral projectile damage, immutable specs,
resource recovery, explicit Story elemental effects, animation pose changes and
transitions, swept melee/one-hit behavior, heal/buff dispatch and God Mode.
Run the normal Story/Create integration checks as well: they verify their
adapters, not a separate set of combat calculations.

Animation type contract: authored animation profiles declare animation_type as Head, Arm, Leg or Movement. Reuse AnimationCastType.begin/drift for cast inertia and CreationLocomotion.cast_legs for posing; do not create mode-specific tuning. Pass animation_type on the authored spell base so CombatSpellRules applies the same tentative Leg physical bonus to the UI and actual launch. New animations must declare type; legacy migration is conservative.

Use AnimationCastType.controls_bone/affects_channel for typed layers and AnimationCastType.emitter for contact restrictions. Head contributions cannot alter torso/legs or emit from hands; Arm and Leg contact points stay in their region; Movement can retain its authored contact point. Composite metadata retains each contribution independently from the overall movement type.

Timed Self Block: Rules.self_barrier_base + Rules.author produce effect=self_barrier with shield_strength and shield_duration. CombatRuntime.release uses the ordinary animation release, resource authorization and cast commitment, then dispatch activates BattleActor.self_barrier. Actor status ticking expires the effect even under editor pose ownership; reset/death clear it. Impact dispatch consumes capacity after physical head/body multipliers and before HP/status/force, so fully absorbed hits apply no physical damage or ragdoll. Ordinary blocks still apply the spell effect. A fully covered hit within SelfBarrier.PARRY_WINDOW (0.12 s after activation) is a perfect parry and suppresses the effect too; overflow damage/effects still pass when capacity is insufficient. The neutral 1s block has exactly 10 capacity, normalized to the same neutral timing amplifier as the default 10-damage physical projectile. BodyBarrierOverlay supplies the shared animated shell. Authoring UI never applies a passive Self coating. tests/timed_self_barrier_test.gd and combat_runtime_contract_test.gd cover this pipeline.

Practice jab: BattleActor.start_left_jab uses the shared left-hand strike and MeleeContact sweep for player key 4 and the Barrier punch tester. It spends stamina only and emits no spell. Spell authoring yields pose control while the shared strike runs. Shield/Absorb/Reflect neutral 1s cast mana is 10/20/30, with activation-wait pricing normalized at the default 0.3s release; Absorb/Reflect remain disabled.

Self Block defaults: 1s cast and lifetime, 10 physical capacity, 10 mana at centered timing. Timing-only perfect refunds up to 5 mana per cast; directional perfect refunds up to 10. Upgrading tiers pays only the difference, capped at max mana. Every normal blocked incoming physical hit charges its full physical damage to stamina through spend_stamina, including the ordinary recovery delay/feedback. Exactly enough stamina succeeds at zero; insufficient stamina clamps to zero, clears the block, and passes the hit/effect through. Fully successful blocks flash the shared body shell green for 0.22s; the 0.12s perfect parry prevents effects, costs zero impact stamina (even at zero stamina), and refunds mana. tests/self_block_resource_test.gd covers these boundaries.

Perfect-parry cast haste: each timing-only perfect grants one additive +10% cast-animation-speed stack (directional perfect grants two) for 1 simulation second, refreshing that shared timer. Actor status ticking owns expiry; reset/death clear all stacks. BattleActor.cast_speed_multiplier is consumed by runtime cast_time and the authoring preview elapsed clock; activation and recovery advance with the animation, while authored duration/costs/damage and unrelated status/locomotion clocks stay unchanged. tests/parry_cast_haste_test.gd covers real parry grants, stacking/refresh/expiry, both cast drivers and reset.

Three block tiers: normal Block (green) covers physical capacity but spends incoming physical damage as stamina and passes effects. Perfect timing (blue) uses the 0.12s activation window, costs zero impact stamina, prevents effects, refunds up to 5 mana and grants one cast-speed stack. Directional perfect (gold) additionally faces within a 30-degree cone of the opposite incoming travel vector; it refunds up to 10 mana and grants two stacks. Incoming travel direction is passed by CombatRuntime, not inferred from the attacker position. Shared actor labels/shell flashes distinguish tiers. tests/block_tiers_test.gd covers the angle boundary, bonuses, refund upgrade/cap, feedback and reset.

Touch authoring prototype: Touch is enabled as a physical-contact delivery, with left/right hands, elbows, knees, feet or head selected explicitly. Additional contacts use the shared 25% stamina surcharge. Rules.touch_base + author produce a timed effect=touch spec. CombatRuntime.release arms it at the cast marker; step_touch_casts reuses MeleeContact swept queries for those selected bones only, with one connected hit per cast, no projectile and no hit at range. finish_cast/interruption/death disarm it. The same runtime works in any CombatWorld; contact physics and costs are not implemented in the authoring panel. tests/touch_cast_workspace_test.gd verifies actual animated hits, incorrect-limb misses, range and cleanup. Contact selection advances with Next to Physical/Fire effects. TouchContactVisual is actor-owned: it extracts immutable skinned body regions for white physical outlines and attaches shared fire plumes to selected contacts. Preview and active-cast sources are separate and visible only during animation playback; shared cast start activates runtime presentation before release, interruption/completion clears it, and reset/death/exit clear stale effects. Fire contact applies the existing shared burn rules without spawning a projectile or ground fire. tests/touch_contact_visual_test.gd verifies the flow, skin bindings, selected regions, original mesh preservation, bone-following flames, real contact burn and cleanup.

CPU melee links and defense timing

Left/right punches are explicit loadout entries. BattleActor.chain_touch_cast
links an already released Touch after 55% of its animation into another Touch.
The old contact window is disarmed, the new hit pays normally at its own release,
and SpellCastMotion blends from the captured pose for 0.10 seconds. Released
projectiles cannot use this route. CPU sequences stop after two links and reserve
stamina; punches and knees can link into each other. tests/touch_combo_test.gd
checks the gates, hand selection, hit-window cleanup and resource accounting.

CPU defense checks every simulation step, forecasts visible projectile arrival
(including cast telegraphs), and aims for impact 50 ms into the existing 120 ms
perfect-parry window. It uses a legal 0.5-second shield animation with ordinary
shared pricing/capacity and tries an evade when activation would be too late.
No parry windows, invulnerability, damage or resource rules are relaxed for AI.
The spectator commentary panel is removed; plans remain in Match report and all resource bars remain on the characters.

Physical flinch recovery: CombatDefenseRules.hit_recovery_seconds owns the shared
non-ragdoll action lockout (about 0.15 s for 10 body damage, 0.21 s for a 20-damage
head hit). Damage and support loss add modest weight, capped at 0.27 s. The
head/chest clips remain distinct. Ragdoll/getup and explicit status stuns retain
their own clocks. CPU thinking is ready immediately after the physical reaction.
tests/hit_recovery_test.gd checks real impacts and immediate counter casts.

Projectile clashes
------------------
CombatRuntime.step_shots calls projectile_clashes.gd before advancing flight.
Opposing teams use continuous relative sphere sweeps, sorted by first contact.
Same-team projectiles pass. Earlier walls, bodies, shields, water contact and
expiry take precedence, using the shared impact predictor. Deterministic shot-ID
ties avoid list-order dependence for simultaneous pairs. Survivors can clash
again in the same step.

Clash strength is the current launch physical damage (movement contribution
already included), before victim-specific headshot or shield calculations.
50 versus 50 consumes both. 60 versus 40 consumes the weaker projectile and leaves
20 damage. The winner retains its effect identity; potency, stored charge contribution and impact mass are
scaled by 20/60 in that example. Water amount inherits the cumulative remaining
power fraction. Speed, radius and effect duration are retained. Reductions copy
mutable specs so authored/shared source data never changes. No resource refund,
character AoE or surface fire is produced by the mid-air clash itself.

CombatWorld.projectile_clash_feedback owns neutral contact feedback/events and
projectile_clash_count. The legacy duel host delegates its former collision code
to the same runtime, retaining its presentation/report counter adapter. CPU
rematches reset the clash count. Contact presentation is owned by the shared
DuelActor base so both classic and extended BattleActors support safe cleanup.

tests/projectile_clash_test.gd verifies equal/unequal damage, reduced burn/force,
fast crossing, array ordering, successive clashes, friendly/near misses, earlier
wall/body impacts and actual residual damage/burn. tests/clash_review.gd checks
the older arena integration.
Touch directional-perfect regression
------------------------------------
Physical and elemental Touch sweeps use the same SelfBarrier perfect-block
rules as projectiles: 120ms timing window, facing within 30 degrees of the
incoming direction, and enough barrier capacity for the physical hit. Gold
directional perfect blocks effects, spends no impact stamina, refunds up to
10 mana and grants two haste stacks; timed-only blue grants the lower reward.
This was already routed through the shared resolver. Added explicit swept-limb
physical/Fire regression coverage, not a separate Touch-only parry mechanic.
Block events now include spell ID, delivery_type and incoming_direction so
diagnostics distinguish Touch golds from projectile golds. See
tests/touch_directional_parry_test.gd for real collision-query coverage of gold,
blue and normal blocks, effect prevention, resource rewards and colored feedback.

Contact push and variable movement
----------------------------------
CombatDefenseRules.contact_body_impulse reduces ordinary non-ragdoll Touch/melee
body translation to 20% of the original impulse, capped at 33.75 kg*m/s (0.45m/s
for a 75kg actor). Accumulated ordinary horizontal push is capped at 0.6m/s,
without truncating an already stronger launch. Skeleton response and leg stamina
chips still use the full original impact. Physical damage, flinch timing, status,
projectile impacts, explicit launches, high charge, Wind, lethal hits and ragdoll
impulses retain their existing rules. Runtime supplies this policy to the common
actor path; modes don't implement their own version. contact_knockback_test.gd
verifies actual swept kick -> punch contact without moving either fighter.

BattleActor.start_motion_jump(height_fraction, held_input) and
start_motion_dash(direction, distance_fraction, held_input) expose variable
movement to any mode/controller. Fractions clamp to 0..1. Default scripted calls
retain full travel. CPU jumps choose smaller heights near an opponent and a
wider height range at distance; dash approach chooses only the distance needed
to reach punching space, and lateral evasion varies its burst length.
Jump choices cost 4..20 stamina. Held jumps charge on the floor over 0.85s,
progressively crouching using jump_charge_pose.gd, and remain at max until release.
Release launches at 5.4..15.6m/s with ordinary gravity and landing; max height is
approximately 5.4m. Exhaustion releases the already-paid charge. Scripted/CPU
fractional jumps share the new height/cost range and retain their short takeoff.
Held dashes begin
at 4, last 0.08..0.30s at 12m/s, and add up to 8 stamina for extended travel.
No extra stamina means the extension ends. Story Space starts/releases a held
jump; releasing W ends a double-tap forward dash. Authored choreography and
legacy special jumps keep their explicit animation behavior.
variable_motion_test.gd measures actual heights, distances, stamina, landing,
low-resource rejection, duplicate takeoff rejection and fractional script calls.

Running into authored attacks
-----------------------------
BattleActor captures the rendered pose when starting an authored cast, blending
into its source over at most 160ms (shortened to finish before release). Touch
chains use the same entry path. Finished casts blend back into idle/locomotion
over 140ms. No animation asset is edited, no contact window is delayed, and
post-release commitment is unchanged.
Shared cast locomotion carries incoming movement, excluding knockback, through
the existing AnimationCastType drag curve. Leg attacks retain their leg pose
and progressively return player movement through the existing recovery rule.
Player arm/head attacks allow movement input; CPUs coast rather than snapping
to a halt. Airborne casts retain their existing gravity and air momentum.
PhysicalMomentum.melee_movement uses the greater of actual horizontal speed and
the still-decaying cast carry, so body capsules stopping root travel immediately
before limb contact do not erase all running momentum. The coefficient remains
3% per m/s, applied once; there is no fixed running/sprinting damage tier, no
extra mana/burn/size bonus, and no momentum retained outside the current cast.
run_attack_transition_test.gd verifies identical first pose, smooth deceleration,
actual static/walking/sprinting knee hits and exact damage, plus clean recovery.

Small cast footwork and perfect Touch counter advantage
-------------------------------------------------------
AnimationCastType.steered_velocity is shared by the live actor and Create's
scripted controller. Early leg casts allow up to 1.0m/s of input footwork;
Movement casts allow 0.65m/s. Steering accelerates at 4m/s^2 and combines with
decaying entry momentum without adding speed above the larger of carry/cap.
Normal input returns through the unchanged recovery curve. The authored leg
pose, actual hitboxes, release timing and commitment remain intact. Live actor
set_cast_movement accepts world-space direction input from script controllers;
CPU Touch casts use modest forward pressure only while outside contact space.

Both timed and directional perfect Touch parries apply attacker recovery of
180ms plus at most 250ms of current follow-through (maximum 430ms from parry).
Ordinary blocks and projectile parries do not apply this penalty. Repeated
contacts refresh the maximum remaining lock instead of adding indefinite stun.
The current animation continues; Touch follow-up links and new cast/legacy
melee starts are denied during recovery, without charging a failed attempt.
Movement remains available. The shared actor status clock expires it and reset
clears it. Existing defender haste/refund rewards remain unchanged. Runtime
emits touch_parry_recovery with attacker/defender/duration for diagnostics.
Tests: cast_footwork_test.gd checks actual pre-release leg/Movement translation,
caps, smooth reversal and normal recovery; touch_directional_parry_test.gd checks
which block tiers apply it; touch_parry_counter_test.gd uses an actual parried
jab and verifies the defender lands the first equal-speed counter punch.

Authored jump composition
-------------------------
animation_jump_motion.gd declares required airborne motion on an animation's
jump_motion metadata: minimum_duration, takeoff and landing fractions. Existing
sources are registered for Rising uppercut (1.35s), Rising kick (1.40s), Tornado
kick (1.65s), and Hurricane kicks (1.85s). Ground sweeps, spinning back kicks and
slide kicks are not automatically classified as jumping merely because they spin.
The shared helper launches the actual CharacterBody using its existing gravity,
