UNIVERSAL COMBAT RUNTIME

The supported gameplay path is:
  mode input -> actor / authored spell -> CombatRuntime -> shared contacts,
  defenses, damage, statuses, resources and physical reactions.
Story and Create both use this path. Modes own selection, camera input, menus,
round objectives and UI. Combat-state presentation belongs to shared actors and
world services, not mode loops: burn, stun, chill, haste and frozen legs must not
branch on story_mode or editor_animation_only. Modes must not calculate hit damage,
subtract a second cast cost or implement a second projectile simulation.

STARTING A NEW MODE

Inherit res://scripts/combat_world.gd, not BattleArena, DuelArena or SpellArena.
CombatWorld is a Node3D with no menu, campaign or demo scene. It supplies actor
registration, services, simulation, hitbox toggles, prediction and event hooks.
Levels are separate geometry/data providers, bound through use_level; see
docs/combat-levels.txt. The default world is unbounded and imports no pit size.

Example GDScript (add your map, camera and light separately):

  extends "res://scripts/combat_world.gd"
  const Rules=preload("res://scripts/combat_spell_rules.gd")

  func _ready() -> void:
      super._ready()
      var player=spawn_combatant(0,Vector3.ZERO)
      var opponent=spawn_combatant(1,Vector3(0,0,4))
      player.brain_enabled=false
      opponent.brain_enabled=false
      round_active=true

  func fire(actor:CharacterBody3D,authored_spell:Dictionary) -> bool:
      var origin=fighter_hand(actor,str(authored_spell.get("hand","hand_r")))
      return combat().release(actor,authored_spell,origin)

The base physics callback advances actors, their real hurtboxes/melee contacts,
projectiles, channels and pulses. If you override it, call tick_combat(delta)
exactly once. Do not also call individual simulation steps in the same frame.
Existing arenas retain their visual and round-management loops and delegate
their simulation stages to the same runtime.

spawn_combatant uses the existing BattleActor and licensed character assets.
The actor owns animation players, locomotion, recovery, defenses, death and
status state. Give actors separate teams to make them enemies. Assign their
input through the shared character movement/focus/camera modules documented in
shared-character-mechanics.txt. story_mode is an existing campaign/control
adapter flag, not a requirement for firing spells through this API.

CASTING API

combat().release(actor,spec,origin,animation_profile={}) -> bool
  Checks active world, living actor, casting-limb availability, optional burst
  requirement, God Mode and both resource budgets. Commits mana and stamina
  atomically, then dispatches the effect. A failed request spawns nothing and
  spends neither resource. The profile supplies limb requirements, not costs.

combat().cast(actor,spec,animation_profile={}) -> bool
  Same request, using the spec's hand as origin. Handles projectile/ground,
  healing, haste, burst, beam, ice beam, nova and earth summon effects.
  Legacy armor dispatch is a compatibility no-op; armor is cosmetic.

Interrupted cast stamina
  begin_cast_attempt(actor,spec,time_to_release,mode_owned=true) snapshots the
  stamina cost and scheduled release time. Advance it with the animation's elapsed
  time using advance_cast_attempt(actor,elapsed). Interrupting/restarting an
  unreleased attempt spends cost * clamp(elapsed/time_to_release,0,1), limited to the
  actor's remaining stamina. Mana is not spent for that interruption.
  Thus 70% of the way to release costs 70%, irrespective of recovery time after
  release. Create converts the timing fraction to seconds; native casts supply
  the release point in the same clock units used by their animation sampler.
  Successful release pays the ordinary full cost once and clears the attempt;
  canceling its recovery cannot charge it again. God Mode remains unlimited.
  Native actor casts and Create use this same accounting. Native casts cancel
  automatically when they leave cast mode; externally driven previews pass
  mode_owned=false and explicitly interrupt on stop/switch/restart.
  Resetting a fighter discards its attempt along with the explicit full reset.

spawn_projectile and combat().dispatch are lower-level execution APIs for callers
that already committed a cast. Do not call them after release for the same cast.

projectile_launch_state / predict_projectile_impact are read-only forecasts.
Movement contribution is captured once at launch. Future caster velocity does
not change an in-flight projectile. AoE applies once per victim, not per limb.
Shared physical_momentum.gd uses horizontal speed equally for forward, backward,
sideways and diagonal motion. Vertical velocity contributes nothing. Projectile
speed increases along the existing aim direction, without sideways aim drift.

spell_impact_burst selects contact presentation from the spell rather than the
attacker's team. Melee and explicit elementless projectiles use a tight neutral
flash/contact marks via ElementalVFX.physical_contact; no flame, smoke or blast
ring. Elemental spells keep their existing bursts. Ground impacts use this same
selection. This changes presentation only, not impact physics, damage or costs.

combat_hit_regions.gd owns physical headshot scaling. apply_impact identifies the
actual receiving area, applies head 2x / other 1x once to its physical component
after shield absorption and before actor health handling, then separately
applies the original status spec. Burn/status potency and duration, mana/stamina,
knockback and nearby-ice damage do not inherit the headshot multiplier. Each AoE
victim resolves its own receiving area. Successful hits notify optional hitbox
highlights, and the common actor uses distinct existing head/chest reaction clips.

combat_defense_rules.gd defines the provisional 40-physical-damage threshold for
nonlethal hit ragdolls. Death retains its ragdoll path. Incoming impulse affects
motion, not the hit threshold. Cosmetic armor cannot absorb damage or impulse.
The authoring panel uses the same pure rule for unblocked body/head predictions.
Barrier/block changes, guard-break policy and a blocking dummy are deferred.

After a successful lethal physical head impact, Runtime calls the actor's optional
sever_head hook. BattleActor splits only that corpse's head skin and releases its
existing ragdoll head. Reset restores intact source meshes. Status tick deaths
never invoke this headshot-only hook, and God Mode/wooden dummies are excluded.

AUTHORING A SPELL

combat_spell_rules.gd owns physical cost/damage from animation duration, release
timing, normalized neutral damage, mana cost, amp, power allocation and authored
projectile specs. animation_mana_scaling.gd owns the existing mana/amp curve.

Rules.allocate(base,mix,element,total_power) applies the chosen power shares.
Rules.projectile_base builds elementless/elemental content without the UI;
Rules.neutral_projectile() is a ready-to-use authored default.
Rules.author(base,duration,release_fraction,offensive) returns a new spec with
final costs, damage, radius, velocity and potency. Rules.authored_stats returns
the matching UI values, including optional moving-caster preview. Author once;
execute that spec unchanged. Do not run author() again when equipping/casting it.

Explicit damage/mana/motion values take precedence. Legacy spell defaults are
content dictionaries, not alternate combat engines. Older duel content keeps
its original preset values while using the same execution pipeline. The neutral
crafted offensive spell remains 1 s, 50/50 size/speed, centered timing and full
power: 10 stamina and 10 damage against an unblocked stationary target.
Mana discounts use only time before release: duration * release_fraction.
The default 1s animation releases at 0.3s, costing ~16.25 mana from a 10 base.
A 4s Fire animation releasing at 30% waits 1.2s: ~17.41 mana before effect transfer.
Effect power now transfers the same fraction of animation stamina into pre-discount
mana. With 28.5% burn, that example transfers 11.4 of its 40 stamina: 28.6 stamina
and (20 + 11.4) * 0.87055 = ~27.34 mana. Damage/amp formulas are unchanged.
Follow-through earns no savings; one second before release is neutral and ten
seconds before release is free. Physical cost/damage and amp keep their own
existing duration rules. Authoring, payment and live calculation windows agree.
Limiter-off overrides stay in spell_test_overrides.gd; the UI's save rejection
still applies. Execution does not recouple independent testing values.

ANIMATION API

After an animated cast successfully releases, CombatRuntime.cast_committed(actor)
blocks voluntary restart/actions until finish_cast(actor). Create preserves the
released animation's duration/profile while draft sliders remain editable for
the next cast. Native actor tick_cast clears commitment on completion. Forced
hit/death mode exits can interrupt; explicit practice reset/scene teardown clears
the lock. Failed releases do not commit, and pre-release cancellation still pays
the completed fraction of stamina. Follow-through is not a second resource fee.

spell_cast_motion.gd samples native or imported animation profiles by normalized
progress. It preserves ice restrictions and supports explicit shared aim-pose
corrections. capture(actor) and blend_from(actor,pose,weight) are shared by cast
transitions and diagonal locomotion. Animation resources stay read-only and
AnimationPlayers remain per actor. animation_channels.gd owns cached filtering.

Mode-specific clocks, charge holds, editor scrubbing/undo and saved timelines
remain their respective controllers' responsibilities; these are authoring and
input state rather than alternate animation assets or damage implementations.
melee_contact.gd consumes an animation's swept limb/window and uses the shared
contact, charge, motion and impact rules. Callers only provide their animation
clock/state and mark a returned successful contact connected.

WORLD HOOKS

Experimental floating numbers

  Burn rules live in burn_rules.gd: 5 seconds, 0.5s tick interval, ~0.3912 base damage
  per tick (~0.7824 DPS / 3.9122 total at potency 1). This calibrates burn to the
  same marginal damage per power point as projectile speed on a 1s body hit.
  Potency/amplification scales damage, not the default duration.
  Actor ticking consumes only remaining active time and catches
  up missed ticks, including the final tick, so frame size cannot change totals.
  Character projectile impacts apply body burn without spawning ground fire.
  Surface impacts leave a five-second fire patch on the actual struck face.
  Wall fire/scorch stays at impact height and attaches to that wall; it is not
  projected onto the ground below. Floor fire stays on the floor. Flame tongues
  rise upward from surface-distributed anchors. Touching wall fire ignites the
  character in 3D; a high patch does not burn someone standing beneath it.
  Each patch ignites a character
  once for the same full burn; standing in it does not refresh the timer each
  frame. Existing explicit burn_duration data can extend either duration later.
  Authoring stats, RHS readouts and execution use these shared rules.
  Cleansing uses actor.cleanse_burn()/Burn.cleanse: clear the remaining duration,
  partial tick clock and source. Already dealt ticks remain; no future burn damage
  is prepaid or queued. Water and reset use the same call. Reapplication starts
  a fresh half-second interval, with no fractional time carried from a cleansed
  burn. The shared visual observes cleared burn state and fades out.
  tests/burn_behavior_test.gd covers actual collision, full totals, large/uneven
  steps, patch lifetime, walk-through ignition, continued burn after exit and amp.
  CombatWorld.set_combat_numbers(enabled) enables a per-world presentation layer.
  It defaults off; Spell creation exposes Numbers [3] and the unmodified 3/numpad
  3 shortcut. Resource spending emits actual successful stamina/magicka costs,
  including interrupted casts. Runtime impacts emit physical damage_taken deltas,
  so immortal training targets still show the actual hit while retaining health.
  Burn ticks emit their actual damage as red typed burn numbers every half-second,
  including immortal practice counters. Regeneration, failed transactions and
  unpaid God Mode costs do not emit numbers. Stamina is green, magicka blue;
  physical and burn damage are red and separately labeled.
  Labels follow their actor, rise, fade over 1.4 seconds and are capped at 32.
  Disabling clears them immediately; battle/practice reset clears old labels.
  combat_floating_numbers.gd owns this rendering; it never calculates or modifies
  damage, costs, physics or actor state. clear_combat_numbers() is the reset hook.

Override projectile_aim_target, combat_target and heal_target to choose targets.
Reuse combat_aim.gd for free aim and focused chest anchors.
Override projectile_visual, orient_projectile, combat_sound, impact_burst,
combat_cast_feedback, combat_heal_feedback and combat_impact_feedback for visuals,
UI and telemetry. These hooks must not apply damage or spend costs again.
finish_round/combat_finished handle mode objectives. CombatLevel supplies optional
bounds, terrain queries and map-local spawns. combat_radius is only a compatibility
adapter for older circular-map scripts, not the generic default.

OWNERSHIP AND LEGACY SEPARATION

combat_world.gd: reusable mode base and hooks; no Create or Story scene required.
combat_runtime.gd: authorization/dispatch, actor and wall steps, projectile
  launch/flight, impacts, channels and pulses.
combat_spell_rules.gd: pure reusable spell construction and balance rules.
combat_diagnostics.gd: optional host logging; shared combat can be imported by
  scripts before UI/autoload setup without depending on a global singleton.
melee_contact.gd: shared swept-limb contact, animation speed/charge and blocking.
duel_actor.gd: shared resource payment/recovery, defense and base actor state.
battle_actor.gd: full actor animation, physical reactions and status handling.
legacy_arena_host.gd: old grassland presentation/capture utilities only.
legacy_spell_catalog.gd: original study spell data.
spell_arena.gd: historical visual-only asset study, not a gameplay superclass.
  Its visual demonstrations have no gameplay damage/resource contract.
duel_arena.gd / battle_arena.gd: existing scene, target, round and presentation
  adapters. Their gameplay simulation delegates to CombatRuntime.
spell_builder.gd: editor controls/preferences and live-preview input adapter.

REGRESSION CONTRACT

tests/combat_runtime_contract_test.gd deliberately uses a bare CombatWorld,
without either the Story or Create scene. It exercises real actor spawning,
atomic failure/success, actual neutral projectile damage, immutable specs,
resource recovery, explicit Story elemental effects, animation pose changes and
transitions, swept melee/one-hit behavior, heal/buff dispatch and God Mode.
Run the normal Story/Create integration checks as well: they verify their
adapters, not a separate set of combat calculations.

Animation type contract: authored animation profiles declare animation_type as Head, Arm, Leg or Movement. Reuse AnimationCastType.begin/drift for cast inertia and CreationLocomotion.cast_legs for posing; do not create mode-specific tuning. Pass animation_type on the authored spell base so CombatSpellRules applies the same tentative Leg physical bonus to the UI and actual launch. New animations must declare type; legacy migration is conservative.

Use AnimationCastType.controls_bone/affects_channel for typed layers and AnimationCastType.emitter for contact restrictions. Head contributions cannot alter torso/legs or emit from hands; Arm and Leg contact points stay in their region; Movement can retain its authored contact point. Composite metadata retains each contribution independently from the overall movement type.
